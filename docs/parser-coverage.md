# Покрытие документов и внешних источников

Проверено по `internal/catalog/products.yaml` и коду worker. Каталог содержит 14 продуктов и 17 видов документов. В репозитории нет набора реальных документов для измерения точности; тесты используют сконструированные образцы. `TEXT_EXTRACTED` означает получение текста и иногда отдельных реквизитов, но не проверку документа.

| Вид документа | Текущее извлечение | Нужные данные и проверка |
|---|---|---|
| `passport` | Текст PDF/Word/изображений | ФИО, серия/номер, дата выдачи, принадлежность заявителю, качество скана; подпись/подлинность не проверяются |
| `bki_consent` | Текст | Субъект, цель, дата, получатель, форма подписи и срок согласия; наличие файла не подтверждает согласие |
| `egrul_extract` | Из текста выписки извлекаются ИНН и ОГРН/ОГРНИП при корректной контрольной цифре | Статус, руководитель, участники, адрес, ОКВЭД, дата выписки и проверка подписи ФНС |
| `account_statement` | CSV с явными английскими или русскими колонками даты, поступления, списания и остатка; UTF-8/CP1251/CP866, рубли с копейками, прямой или обратный порядок строк, сверка соседних остатков; частично формат 1С `1CClientBankExchange` | Владелец и счёт (если не указаны в CSV), подпись и источник, дубликаты; PDF банков и XLSX ещё не разбираются |
| `financial_statements` | Учебный JSON; из текста бухгалтерских форм с явно указанной единицей и годом читаются строки 2110, 2400, 1300, 1400+1500 | Декларация УСН и иные формы; ИНН, корректировка, сравнение годов и контрольные соотношения |
| `marketplace_sales_report` | Учебный JSON и универсальный CSV с колонками месяца, продаж, возвратов и выплат (русский/английский; RUB) | Отдельные адаптеры Wildberries, Ozon и Яндекс Маркета; комиссии, ID продавца и сверка с источником |
| `title_documents` | Текст | Владелец, основание права, объект, ограничения и соответствие заявителю |
| `equipment_purchase_contract` | Текст | Стороны, оборудование, цена, дата и условия передачи |
| `equipment_specification` | Текст | Модель, серийный номер, количество и цена; связь с договором |
| `vehicle_registration` | Из текста ПТС/СТС извлекается VIN с явной подписью поля | Собственник, марка, модель, год, регистрационные данные и сверка с автомобилем |
| `egrn_extract` | Из текста выписки извлекается кадастровый номер при явной подписи поля | Правообладатель, площадь, обременения, дата и электронная подпись |
| `technical_passport` | Текст | Адрес, идентификатор и характеристики объекта, дата документа |
| `valuation_report` | Учебный JSON | Объект, собственник, оценщик, дата оценки, подтверждённая стоимость, допущения; отделять от заявленной клиентом цены |
| `business_plan` | Текст | Период прогноза, допущения, прогноз денежных потоков и связь с приобретаемым бизнесом |
| `target_financial_statements` | Учебный JSON и те же строки из текста бухгалтерских форм | ИНН и периоды должны относиться к целевому бизнесу; сверка с источником |
| `business_purchase_contract` | Текст | Стороны, объект/доли, стоимость, дата и условия сделки |
| `preliminary_purchase_contract` | Текст | Стороны, объект, цена, первоначальный взнос, сроки |

## Проверенные источники форматов

- ФНС: [сервисы ЕГРЮЛ/ЕГРИП и «Прозрачный бизнес»](https://www.nalog.gov.ru/donline/), [действующая форма и формат УСН](https://www.nalog.gov.ru/rn77/about_fts/docs/16598752/), [ресурс бухгалтерской отчётности](https://bo.nalog.gov.ru/faq).
- 1С: [формат обмена с «Клиентом банка»](https://v8.1c.ru/tekhnologii/obmen-dannymi-i-integratsiya/standarty-i-formaty/standart-obmena-s-sistemami-klient-banka/formaty-obmena/).
- Банк России: [кредитная история и согласие субъекта](https://www.cbr.ru/ckki/).
- Яндекс Маркет: [виды отчётов и API](https://yandex.ru/dev/market/partner-api/doc/ru/step-by-step/reports); Wildberries: [категории API и отчётов](https://dev.wildberries.ru/knowledge-base/articles/019d49a0-ea5d-74b7-a147-be50f8dda5e9/kak-pol-zovat-sia-dokumentatsiei-wb-api).

Подключения к этим сайтам и сервисам пока отсутствуют. Их страницы описывают возможные источники и форматы, но не служат тестовыми данными для парсера.

## Что требуется для проверки на реальных документах

Нужен согласованный набор образцов с метками: тип документа, источник/версия формата, период, ожидаемые поля и значения, допустимое расхождение, причина отказа или ручной проверки. Проверять следует отдельно полноту извлечения, точность каждого поля и отсутствие неверно подтверждённых значений. Документы с персональными данными нельзя добавлять в обычные тестовые фикстуры без обезличивания.

Каталог проверяет наличие файла при отправке заявки, а не его содержание, принадлежность заявителю или подпись. Для залога сейчас требуются одинаковые документы независимо от типа объекта; альтернативы вроде ЕГРН **или** спецификации оборудования ещё не выражены в правилах. До их реализации извлечение текста не должно считаться успешной проверкой документа.
