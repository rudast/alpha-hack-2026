# Тестовые сценарии

Сценарии 1–2 и A1–A10 реализованы и проверены на запущенном стеке, остальные описывают целевое поведение. Тестовые учётные записи перечислены в [README](../README.md#тестовые-учётные-записи).

| # | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | Вход клиента по телефону или по почте и паролю, затем код 2FA | Токен и `redirect: /personalAccount` |
| 2 | Вход сотрудника по почте или по телефону и паролю, затем код 2FA | Токен и `redirect: /employee` |
| 3 | Клиент с Debt/Equity больше 2 подаёт заявку | Скоринг ухудшается, заявка уходит в `MANUAL_REVIEW`; отказ или встречное предложение с причиной принимает сотрудник |
| 4 | Клиент с Debt/Equity не больше 2 подаёт заявку | Долговая нагрузка не мешает одобрению |
| 5 | Переход к заявке из кабинета | ИНН и тип организации (ИП или ООО) подставлены автоматически |
| 6 | Переход к заявке со страницы входа | ИНН и тип организации вводятся вручную |
| 7 | Отправка заявки с пустыми обязательными полями | Отправка блокируется, фокус на первом пустом поле |
| 8 | Заявка без подписанных согласий на БКИ | Отправка блокируется |
| 9 | Полная заявка, хороший скоринг | `SUBMITTED → DATA_CHECK → SCORING → APPROVED`, статусы видны клиенту |
| 10 | Заявка с недостающими данными | `INFO_REQUESTED`, клиент отвечает внутри заявки |
| 11 | Сложный случай или негативный скоринг | `MANUAL_REVIEW`, решение принимает андеррайтер |
| 12 | Встречное предложение | Клиент может принять, изменить параметры или подать заново |
| 13 | Отказ (выносит сотрудник) | Показаны причина и альтернативные продукты (меньшая сумма, больше залога) |
| 14 | Подписание и выдача | `SIGNING → SIGNED → DISBURSED → ACTIVE`, кредит появляется в кабинете |

## Вход и коэффициент долговой нагрузки

| # | Сценарий | Ожидаемый результат |
|---|---|---|
| A1 | Клиент `+79990000002` (данных нет) вызывает `/me/bootstrap` | Данные запрошены у воркера: долг 2 400 000, капитал 4 000 000, коэффициент 0,6 |
| A2 | Клиент `+79990000003` (данные 2-дневной давности) | Данные обновлены воркером: долг вырос до 1 800 000 |
| A3 | Клиент `+79990000001` (данные свежие) вызывает `/me/bootstrap` дважды | Воркер не вызывается, `fetched_at` не меняется |
| A4 | Клиент `+79990000004` | Коэффициент 3,5, выше порога 2 |
| A5 | Три неверных пароля подряд, затем верный | 401, 401, 401, затем 429: вход заблокирован на 15 минут |
| A6 | Неверный код 2FA | 401; после трёх неверных кодов challenge аннулируется |
| A7 | Неизвестный телефон, неверный пароль, почта сотрудника в роли клиента | Один и тот же ответ 401 |
| A8 | Запрос `/me/bootstrap` без токена; токеном сотрудника | 401; 403 |
| A9 | Воркер выключен, данных у компании нет | 503 примерно через 8 секунд |
| A10 | Воркер выключен, данные устарели | 200 с прежними значениями |
| A13 | Воркер ответил `{"error": "..."}`, данные устарели | 200 с прежними значениями, причина в логе API |
| A14 | Воркер ответил ошибкой или не JSON, данных не было | 503, причина в логе API |
| A15 | Воркер прочитал сообщение и упал, затем запущен новый | Через 30–40 секунд зависшее сообщение забрано и обработано, в списке ответов появился ответ |

## Заявки клиента (черновик, просмотр, отправка)

Реализовано и проверено в `scripts/smoke.sh`. Без очереди: после отправки заявка остаётся в `SUBMITTED`, задача воркеру скоринга пока не уходит.

| # | Сценарий | Ожидаемый результат |
|---|---|---|
| B1 | Первое сохранение формы: `POST /applications` | 201, статус `DRAFT`, компания и автор взяты из сессии |
| B2 | Создание с неизвестным продуктом или отрицательной суммой | 400 |
| B3 | Автосохранение: `PATCH /applications/{id}` с актуальной `version` | 200, изменены только переданные поля, `form` заменена целиком, версия выросла на 1 |
| B4 | Список заявок | 200, только заявки своей компании, от новых к старым |
| B5 | Чужая заявка: просмотр, изменение, отправка; некорректный id в адресе | 404 во всех случаях (чужая неотличима от несуществующей) |
| B6 | Отправка неполной заявки | 422 `{"missing_fields": [...]}`, поля формы вида `группа.поле` |
| B7 | Отправка полной заявки | 200, статус `SUBMITTED`, в `history` запись `DRAFT → SUBMITTED` |
| B8 | Повторная отправка и изменение после отправки | 409 |
| B9 | Продукт недоступен компании (продукт только для ООО, компания ИП) или срок вне диапазона | 422 `{"error": ...}` |
| B10 | Методы заявок без токена или токеном сотрудника | 401, 403 |
| B11 | `PATCH` по устаревшей `version` (заявку уже изменила другая вкладка) | 409, чужие изменения не затёрты |
| B12 | `PATCH` без `version` | 400 |
| B13 | Десять одновременных `PATCH` с одной версией и разными ключами | один 200, остальные 409, версия выросла ровно на 1 |
| B14 | `POST`/`PATCH` по заявкам без `Idempotency-Key` | 400 |
| B15 | Повтор создания, сохранения или отправки с тем же ключом и тем же телом | тот же ответ, действие не выполнено второй раз (второго черновика нет, версия не выросла) |
| B16 | Тот же ключ для другого запроса | 422 |
| B17 | Десять одновременных созданий с одним ключом | создан ровно один черновик, все ответы про него |
| B18 | Новая отправка уже отправленной заявки с новым ключом | 409 |
| A11 | Вход по почте `client2@example.test` вместо телефона | Тот же пользователь и та же компания, что при входе по `+79990000002` |
| A12 | Две неверные попытки по телефону и одна по почте того же пользователя, затем верный пароль | 429 или 401: блокировка общая для обоих логинов |
